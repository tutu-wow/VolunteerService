# <font style="color:#48b378;">一、项目概述</font>
<font style="color:#262626;">智慧志愿服务管理系统采用前后端分离架构，面向志愿者和管理员构建“活动发布—在线报名—后台审核—现场签到—积分激励—心得沉淀—社区交流—公益兑换”的志愿服务闭环。志愿者可浏览和检索活动、提交报名、收藏感兴趣的活动、查看报名进度、发布服务心得，并通过社区交流志愿服务经验；完成活动签到后，系统依据积分规则形成积分记录，志愿者可在积分商城中兑换公益纪念品。管理员负责志愿者账号、活动类型、活动内容、报名审核、签到记录、心得内容、积分商品、兑换履约、公告消息及社区内容的统一维护，并通过数据看板了解平台运营情况。</font>

# <font style="color:#48b378;">三、核心功能与实现说明</font>
### <font style="color:#262626;">3.1 双角色认证、账号维护与访问控制</font>
<font style="color:#262626;">系统设置管理员和志愿者两类角色。用户使用账号、密码和角色登录后，服务端校验账号信息并签发携带用户标识、角色信息的 JWT；前端保存登录状态，在后续请求中携带 Token。服务端拦截器解析当前用户信息，前端根据角色呈现管理端或志愿者端功能入口。志愿者可完成注册、资料维护、密码修改和密码找回；管理员可按账号、姓名、邮箱、手机号和角色查询用户，并进行账号新增、编辑、启用禁用、密码重置与 Excel 导出等操作。</font>

<font style="color:#9d174d;">注册或登录 → 服务端校验账号与角色 → 签发 JWT → 前端保存登录状态 → 请求携带 Token → 服务端解析当前用户 → 按角色开放对应功能入口</font>

| **业务场景** | **系统处理结果** |
| :--- | :--- |
| <font style="color:#262626;">身份认证</font> | <font style="color:#262626;">登录成功后返回 JWT，Token 中保存用户 ID 与角色信息；当前用户拦截器解析请求身份，供活动审核、签到等业务读取当前操作人。</font> |
| <font style="color:#262626;">志愿者注册</font> | <font style="color:#262626;">注册时校验账号唯一性，并对已填写的邮箱和手机号进行重复校验；密码经过处理后再写入账号数据。</font> |
| <font style="color:#262626;">账号维护</font> | <font style="color:#262626;">志愿者可维护个人资料、修改密码或根据绑定的手机号、邮箱找回密码；列表查询不会向前端返回密码字段。</font> |
| <font style="color:#262626;">后台账号管理</font> | <font style="color:#262626;">管理员可按多种条件分页查询账号，执行新增、编辑、启用禁用、重置密码、单条或批量删除及导出操作。</font> |


### <font style="color:#262626;">3.2 活动分类、活动发布与报名审核</font>
<font style="color:#262626;">管理员先维护志愿活动类型，再发布活动标题、图文介绍、服务地点、报名起止时间、活动起止时间、人数上限、积分奖励、签到奖励和技能要求等信息。系统根据报名开始时间、报名截止时间及活动时间计算活动的报名中、进行中、已结束和已取消状态。志愿者可按活动类型、关键词和状态检索活动，在详情页了解服务时间、地点、名额和积分信息，并提交报名理由或收藏活动。报名时系统校验活动当前可报名、名额未满且用户尚未存在有效报名记录；管理员审核通过后更新审核信息并增加活动当前参与人数，审核拒绝时保留审核结果和说明。</font>

<font style="color:#9d174d;">维护活动类型 → 发布活动与报名规则 → 志愿者按条件浏览活动 → 查看详情并提交报名 → 系统校验时间、名额与重复报名 → 管理员审核通过或拒绝 → 志愿者在“我的报名”查看处理结果</font>

| **功能环节** | **系统处理结果** |
| :--- | :--- |
| <font style="color:#262626;">活动类型与发布</font> | <font style="color:#262626;">活动关联类型、发布人、图文内容、地点、服务时间、报名时间、人数上限、技能要求及积分配置，为分类展示和运营维护提供基础数据。</font> |
| <font style="color:#262626;">动态状态计算</font> | <font style="color:#262626;">系统依据当前时间与报名开始、报名截止、活动开始及结束时间计算展示状态，避免依赖人工频繁修改活动进度。</font> |
| <font style="color:#262626;">报名校验</font> | <font style="color:#262626;">仅报名中活动允许报名；已取消、进行中或已结束的活动不能提交报名，同时校验人数上限与同一用户的重复有效报名。</font> |
| <font style="color:#262626;">审核与收藏</font> | <font style="color:#262626;">管理员可审核通过或拒绝报名，并记录审核人、审核时间和备注；志愿者可建立活动收藏记录，在个人中心集中查看感兴趣的活动。</font> |


### <font style="color:#262626;">3.3 签到码服务、积分奖励与积分明细</font>
<font style="color:#262626;">活动报名审核通过后可关联签到码，管理员在现场输入签到码完成签到。系统根据签到码定位报名记录，校验报名状态为审核通过、活动存在且未产生过签到记录，再创建签到数据。签到成功后，系统分别按活动奖励和签到奖励写入积分记录，使志愿者参与服务的成果可追溯。管理员可维护积分规则的编码、积分值、有效天数、说明和启用状态；志愿者可查看累计积分、已获得积分、已消耗积分和每笔积分变动明细，并在积分排行榜中查看志愿服务参与情况。</font>

<font style="color:#9d174d;">报名审核通过并生成签到码 → 管理员输入签到码 → 校验报名、活动与重复签到 → 创建签到记录 → 写入活动奖励和签到奖励积分 → 志愿者查看积分明细与排行</font>

| **积分场景** | **系统处理结果** |
| :--- | :--- |
| <font style="color:#262626;">现场签到</font> | <font style="color:#262626;">签到码只能匹配审核通过的报名记录；系统阻止无效签到和同一志愿者在同一活动中的重复签到。</font> |
| <font style="color:#262626;">积分规则</font> | <font style="color:#262626;">规则包含规则名称、规则编码、积分值、有效天数、说明和启用状态，支持管理员根据平台激励方案维护。</font> |
| <font style="color:#262626;">积分记录</font> | <font style="color:#262626;">积分记录关联志愿者、活动和积分规则，保存积分变动、积分类型、过期时间、过期标记和业务备注，覆盖活动奖励、签到奖励、兑换扣减和积分过期等类型。</font> |
| <font style="color:#262626;">积分统计</font> | <font style="color:#262626;">志愿者端汇总可用、已获得和已消耗积分，并展示积分排名；管理员端可按时间统计积分发放情况。</font> |


### <font style="color:#262626;">3.4 积分商城、地址维护与兑换状态流转</font>
<font style="color:#262626;">平台通过积分商城将志愿服务激励延伸到公益兑换场景。管理员可维护积分商品名称、说明、图片、所需积分、库存、兑换数量、上架状态和排序；志愿者可浏览上架商品，选择收货地址并提交兑换。系统创建兑换记录前会计算用户可用积分并检查商品库存，兑换成功后扣减库存、增加商品兑换数量，并写入对应的积分兑换记录。兑换记录在待发货、已发货、已收货和已取消之间流转，管理员可填写发货备注，志愿者可确认收货；取消待发货兑换时，系统同步恢复库存和兑换数量，并移除相应的扣分记录。</font>

<font style="color:#9d174d;">浏览上架商品 → 维护并选择收货地址 → 校验可用积分与库存 → 创建兑换记录、扣减库存和积分 → 管理员发货 → 志愿者确认收货；待发货订单取消时恢复库存和积分扣减记录</font>

| **交易场景** | **系统处理结果** |
| :--- | :--- |
| <font style="color:#262626;">商品维护</font> | <font style="color:#262626;">管理员可维护商品图文、所需积分、库存、上架状态和展示顺序，并查看累计兑换数量。</font> |
| <font style="color:#262626;">地址与兑换</font> | <font style="color:#262626;">志愿者可新增、编辑和选择收货地址；兑换记录保留商品、数量、所耗积分、收货人、联系电话、收货地址与地址关联信息。</font> |
| <font style="color:#262626;">库存和积分校验</font> | <font style="color:#262626;">提交兑换时必须满足可用积分不少于兑换所需积分且商品库存充足；成功后同步更新商品库存、兑换次数和积分流水。</font> |
| <font style="color:#262626;">履约处理</font> | <font style="color:#262626;">管理员仅可对待发货记录执行发货并登记备注；志愿者仅可对已发货记录确认收货，待发货记录取消后自动执行库存与积分回退。</font> |


### <font style="color:#262626;">3.5 服务心得、社区互动与内容沉淀</font>
<font style="color:#262626;">为沉淀志愿服务过程中的真实经验，志愿者可围绕参与过的活动发布图文心得，管理员可对心得进行审核通过或拒绝，并保存审核人、审核时间和审核说明。系统同时提供志愿服务社区，志愿者可发布帖子、添加图片、浏览帖子详情、评论和回复其他用户的评论；点赞功能分别记录目标类型和目标标识，以避免同一用户对同一目标重复点赞。帖子、评论、点赞与浏览数据形成可追踪的互动记录，管理员可统一维护帖子分类、帖子内容、评论及点赞记录。</font>

<font style="color:#9d174d;">参与活动 → 发布图文服务心得 → 管理员审核通过或拒绝 → 在社区发布服务话题 → 用户浏览、评论、回复和点赞 → 系统汇总互动数量 → 管理员统一维护社区内容</font>

| **互动能力** | **系统处理结果** |
| :--- | :--- |
| <font style="color:#262626;">心得发布与审核</font> | <font style="color:#262626;">心得关联志愿者和活动，保存标题、正文、图片、审核状态、审核意见及审核信息，支持在“我的心得”中持续管理。</font> |
| <font style="color:#262626;">帖子交流</font> | <font style="color:#262626;">帖子保存作者、标题、内容、图片、浏览量、点赞量、评论量和状态；前台提供帖子列表、详情和个人发帖管理。</font> |
| <font style="color:#262626;">评论回复</font> | <font style="color:#262626;">评论关联具体帖子和评论人，通过父评论标识组织回复关系，形成围绕志愿活动和服务心得的交流内容。</font> |
| <font style="color:#262626;">点赞统计</font> | <font style="color:#262626;">点赞记录关联用户、目标和目标类型，支持帖子及评论的点赞；系统根据记录数量汇总帖子互动数据。</font> |


### <font style="color:#262626;">3.6 公告消息与个性化活动推荐</font>
<font style="color:#262626;">管理员可发布平台公告，并向指定志愿者发送系统、活动、审核或兑换等类型的消息。志愿者首页展示已发布公告、热门活动、积分概览和积分排行；消息中心支持按类型查看消息、查看未读数量、单条标记已读和一键全部已读。对于已登录志愿者，系统基于报名、收藏和签到行为提供个性化活动推荐：报名、收藏、签到分别作为不同权重的偏好信号，系统计算用户之间的余弦相似度，选取相似用户参与但当前用户未参与的未结束活动；当用户行为不足或推荐数量不足时，再使用热门活动补充结果。</font>

<font style="color:#9d174d;">管理员发布公告或创建消息 → 首页和消息中心按条件加载 → 志愿者阅读后更新已读状态；汇总报名、收藏、签到行为 → 计算相似用户 → 推荐未参与的可用活动 → 热门活动补足推荐结果</font>

| **服务能力** | **系统处理结果** |
| :--- | :--- |
| <font style="color:#262626;">公告展示</font> | <font style="color:#262626;">公告维护发布状态和内容，已发布公告在志愿者首页轮播展示；公告列表接口使用 Redis 缓存热点分页结果，并在公告变更时清理对应缓存。</font> |
| <font style="color:#262626;">消息中心</font> | <font style="color:#262626;">消息关联接收人、标题、内容、消息类型和业务关联标识，志愿者可按消息类型筛选，并更新单条或全部消息的已读状态。</font> |
| <font style="color:#262626;">协同过滤推荐</font> | <font style="color:#262626;">报名、收藏、签到行为分别按 3、2、5 的权重构建用户—活动评分矩阵，通过余弦相似度选取相近用户的活动偏好。</font> |
| <font style="color:#262626;">推荐兜底与更新</font> | <font style="color:#262626;">推荐结果排除当前用户已参与、已结束和已取消的活动；无行为或推荐数量不足时按活动热度补充，报名与收藏变化时同步清理对应用户的推荐缓存。</font> |


### <font style="color:#262626;">3.7 AI 志愿服务问答与流式会话管理</font>
<font style="color:#262626;">平台接入 DeepSeek 模型，提供面向志愿服务场景的 AI 智能助手。用户可新建或选择会话并提问，服务端先保存用户消息，再读取当前用户、当前会话最近的历史记录作为上下文，将系统提示词、历史消息和当前问题一同提交给模型。模型以流式方式返回内容，服务端将生成片段通过 SSE 持续推送至前端，用户无需等待完整回答即可查看回复；生成结束后，系统再将完整 AI 回复保存为助手消息。会话列表按最新消息时间展示，用户可查看某一会话的历史记录，也可删除不再需要的会话及其关联消息。</font>

<font style="color:#9d174d;">创建或选择会话 → 保存用户问题 → 读取当前会话最近消息 → 调用 DeepSeek 流式生成 → SSE 持续推送回答片段 → 保存完整助手回复 → 更新会话最新消息并支持历史查询或删除</font>

| **AI 能力** | **系统处理结果** |
| :--- | :--- |
| <font style="color:#262626;">场景化问答</font> | <font style="color:#262626;">系统提示词限定 AI 以志愿服务平台助手身份回答，帮助用户了解平台功能、志愿活动信息及常见志愿服务问题。</font> |
| <font style="color:#262626;">流式输出</font> | <font style="color:#262626;">后端以 </font>`<font color="#262626">text/event-stream</font>`<font style="color:#262626;"> 返回生成片段，前端逐步拼接和展示内容，降低用户等待完整回复时的空白感。</font> |
| <font style="color:#262626;">上下文隔离</font> | <font style="color:#262626;">聊天记录同时关联用户和会话标识，每次请求只读取当前用户当前会话的最近历史，保证不同用户及不同话题之间的数据独立。</font> |
| <font style="color:#262626;">会话管理</font> | <font style="color:#262626;">系统按会话汇总最新消息和时间，支持获取会话历史；删除会话时同步删除该会话下的聊天记录。</font> |


### <font style="color:#262626;">3.8 运营数据看板与后台综合维护</font>

<font style="color:#9d174d;">用户、活动、报名、心得和积分记录 → 服务端按条件分页与聚合查询 → 输出总量、趋势、分布和排行数据 → ECharts 渲染管理首页 → 管理员进入业务模块进行维护和数据导出</font>
